### 正则完胜的一项：能否破净（有无净资产下限）
交叉表只有三种组合，**不存在 LLM=PRESENT 但正则=False 的情况**：

  LLM=UNKNOWN & 正则=False -> 134
  LLM=UNKNOWN & 正则=True  ->  20  ← LLM 漏抽，正则补回
→ **正则是 LLM 的严格超集**。只用正则 175 只全覆盖(56.6%)，
  只用 LLM 155 只(50.2%) 漏 20 只。两条腿并集也是 175 —— LLM 这一项冗余。
→ **lt_bps 这一项完全可以改成纯正则 pipeline，省掉 LLM 调用。**

### 但 LLM 压倒性胜出的：需要精确取值/跨句关联的字段
| 字段 | LLM | 正则 |
|---|---|---|
| trigger_ratio | 98.7% | 16.2%（还只是候选列表）|
| observation_window | 96.8% | 49.5%（候选列表）|
| meeting_price_bases | 99.7% | avg_20=31.4% avg_1=12.9% |

### 深层规律（重要）
**二值判定 + 句式固定 → 正则优（免费、确定、可回溯、超集）**
**精确取值 / 多值绑定 / 跨句结构 → LLM 优（正则写不出来或退化为候选列表）**
另：41 个字段里正则只能碰约 6 个；coupon_schedule(6档利率绑定年份)、put 全套、
redemption 全套、投票比例 2/3、回避条款等语义型字段正则根本做不了。

### 正则的隐藏风险（要提醒）
AVG_1 正则漏写「个」字的容错 → 召回率从应有值掉到 12.9%，**静默失效无从察觉**。
LLM 至少答 UNKNOWN 是个信号。故纯正则方案必须配"召回率监控"，否则降质无声。

### 1. readjust_dt —— 免费可得（adj_type=U 接口）

  记录里字段名就叫 **readjust_dt**（= 计数重新起算日，通常 = 董事会决议日 + 1）。

### 2. drdays 语义（免费字段，关键）
- `drdays < 0` 时：`|drdays| = (快照日 2026-10-01 − readjust_dt).days`，即距上次转股价/计数重置的自然日数。
- `drdays = None` ⟺ `readjust_dt = '-'`（88 只，转股价从未调整过）→ 无锚点，用满窗口。
- 可直接反推锚点：`readjust_dt = 20261001 − |drdays|`。

### 3. adjust_count —— 免费可得
- 直接式：`adjust_count = required_days − adjust_remain_days`（remain 是免费字段）。
- 自算式（引擎）：区间 = 最近 `window` 个交易日 ∩ [readjust_dt, 最新交易日]，
  数「收盘价 < 转股价×比例」的交易日数，封顶 required_days。
- 实测口径细节：窗口取 `closes[-(W-1):]`（比条款窗口少 1，实测最优）、锚点日当天**计入**（>=）。
- **与集思录 remain 反推值比对：50 只可比对，45 只一致（90%）**。
- 残留 5 只：先锋/佩蒂（疑上市日或未被 U/D 日志记录的转股价调整截断窗口）、
  震裕转02（疑复权口径）、宜化/龙星（阈值临界 0.007 元，数据源差异）。
- 已落盘 `adjust_count_result.json`（319 只，含 display "14|15|30" 格式）。

### 4. unadj_tips 解码

  垒知 127062 = 32 条 U 记录，完全对上。
- `adj_tips` 形如 `'S S'`/`'F S'`：S=下修成功、F=失败，条数 = D 日志条数。
